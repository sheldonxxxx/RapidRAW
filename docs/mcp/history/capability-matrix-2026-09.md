# RapidRAW application, MCP implementation, and test coverage

> **Historical snapshot — September 2026.** This document is a dated evidence record, not the live tool inventory or current support matrix. Live runtime capability comes from `rapidraw_capabilities` and the current setup/reference docs. The measurements and claims below are preserved as recorded, not rewritten to look current.

This inventory describes this checkout on 2026-09-14. The desktop feature list comes from the [application README](../../../README.md), [registered native commands](../../../src-tauri/src/lib.rs), and [UI adjustment definitions](../../../src/utils/adjustments.ts). MCP availability comes from the [native dispatch](../../../src-tauri/src/mcp_bridge/operations.rs) and [public tool schemas](../../../mcp/src/tools.ts), not the upstream downloadable application. There are 65 public tools: 60 native methods and five host operation-job methods. All tool names below have the `rapidraw_` prefix.

The three local enhancement additions are `enhancement_models`, `install_enhancement_model` and `enhance`. They expose learned mask refinement, scene/portrait-part segmentation, experimental deblur and 2× enlargement, with captured worker support. See the [model, hardware and validation guide](../../../docs/local-enhancement.md); these additions are separate from the historical 62-tool acceptance counts below.

**Implementation is distinct from evidence.** A successful native call proves execution; an assertion checks a stated contract; a pixel assertion independently inspects rendered output. Neither establishes photographic quality. The suites linked below contain those checks and write separate evidence for each level. **Broad macOS acceptance before point refinement: all 62 tools have successful calls across 1,490 actual MCP calls and 202 explicit checks, using one frozen native binary and runtime.** These are reported validation results. Use the checked-in [test instructions](../testing.md#running-the-suites) and [coverage aggregator](../../../mcp/scripts/coverage-report.mjs) to generate a report for your build. Of 1,893 tool/parameter/adjustment requirements, 1,219 still lack evidence after correcting seven retouch-attribution paths; nested settings are not exhaustively covered. See [the verification record](verification-2026-09.md) for exact counts, two environment-dependent skips and the separate seven-photo visual review. The newer [point-refinement contract](../subject-refinement.md) and focused follow-up are reported against their own build in the verification record. Test scripts alone do not prove a passing run.

JPEG XL opaque exports retain the lossy quality mapping; quality 100 is lossless at the supported eight-bit output depth. Transparent output larger than 256 pixels on either axis uses a lossless compatibility path and returns an explicit export warning that quality is not applied and file size can increase. Native RGB/RGBA eight- and sixteen-bit input regressions decode the actual output and compare lossless pixels.

Session fork and bundle import/export are synchronous operations. Model installation is synchronous; it is not included in the operation-job enum.

The MCP also exposes workflow/schema/session resources and the `pro_photo_edit` prompt. Their registration and protocol contracts are tested separately from native image processing; a prompt is not an autonomous photographic-quality guarantee.

Each run ledger is generated from discovery on the actual binary, including every tool schema and adjustment leaf. [Coverage aggregation](../../../mcp/scripts/coverage-report.mjs) rejects native evidence when the executable or runtime sources changed during the run, and preserves unsuccessful attempts. A parameter without an explicit assertion remains an evidence gap even when its containing tool has a successful call. See [verification](verification-2026-09.md), [portable workflow details](../portable-sessions.md), and [geometry/review contracts](../geometry-review.md) for scope and limitations.

See the [remaining-gap assessment](gap-assessment-2026-09.md) for priorities, difficulty estimates, and proposed acceptance criteria.
